01. Fundamentos de Arquitectura

Arquitectura Global del Sistema

FightConnect está construida como una Aplicación Multi-Página (MPA) modular basada en JavaScript ES6 nativo y el empaquetador Vite, eliminando la sobrecarga de frameworks monolíticos.

CLIENTE (MPA)
Vanilla JS Modules + CSS3 Tokens
• Enrutamiento por archivos HTML
• Three.js 3D Canvas
• Canvas Image Compressor WebP
VITE DEV & BUILD ENGINE
Rollup Bundle + Local Middleware
• Dynamic Entry Points Scan
• /api/upload-image (Multer disk)
• Output: Zero-config static MPA
BACKEND FIREBASE
Cloud Firestore + Auth + Storage
• Autenticación segura (Tokens JWT)
• Firestore NoSQL (users, events)
• Reglas Perimetrales Anti-Tamper

Seguridad Perimetral

Guardián de Rutas RBAC (`protegerRutas`)

Mecanismo cliente-servidor que evita accesos no autorizados a vistas privadas mediante verificación en memoria de userRole.

js/app.js · Función protegerRutas() 
function protegerRutas() {
    const rolActual = localStorage.getItem('userRole');
    const paginaActual = window.location.pathname;

    // 1. Excepción Pública (Páginas informativas, carteleras y manuales)
    if (
        paginaActual.includes('local.html') || 
        paginaActual.includes('internacional.html') || 
        paginaActual.includes('noticias.html') || 
        paginaActual.includes('evento-detalle.html') ||
        paginaActual.includes('sanciones.html') ||
        paginaActual.includes('terminos.html') ||
        paginaActual.includes('privacidad.html') ||
        paginaActual.includes('media-kit.html') ||
        paginaActual.includes('manual-usuario') ||
        paginaActual.includes('manual-programador') ||
        paginaActual.includes('fightfeed.html') ||
        paginaActual === '/' || paginaActual === ''
    ) {
        return; // Paso libre permitido
    }

    // 2. Bloqueo de No Autenticados
    if (!rolActual && !paginaActual.includes('index.html')) {
        window.location.href = 'index.html';
        return;
    }

    // 3. Validación Cruzada de Privilegios por Rol
    if (rolActual === 'fighter' && (paginaActual.includes('promotor-') || paginaActual.includes('fan-'))) {
        window.location.href = 'fighter-dashboard.html';
    } else if (rolActual === 'promoter' && (paginaActual.includes('fighter-') || paginaActual.includes('fan-'))) {
        window.location.href = 'promotor-dashboard.html';
    } else if (rolActual === 'fan' && (paginaActual.includes('fighter-') || paginaActual.includes('promotor-'))) {
        window.location.href = 'fan-dashboard.html';
    }
}
Backend Hardening

Reglas de Seguridad Firestore (`firestore.rules`)

Políticas perimetrales NoSQL que blindan colecciones contra manipulación maliciosa de privilegios y escalado de roles.

firestore.rules · Reglas de Colecciones Principales 
match /users/{userId} {
    allow read: if true;
    allow create: if isOwner(userId) && (!('isVerified' in request.resource.data) || request.resource.data.isVerified == false);
    allow update: if isOwner(userId) && (
        // Bloquea que un usuario se auto-verifique a Nivel 2
        !('isVerified' in request.resource.data) || request.resource.data.isVerified == resource.data.isVerified
    );
}

match /events/{eventId} {
    allow read: if true;
    allow create: if isAuthenticated() && request.resource.data.promoterId == request.auth.uid;
    allow update, delete: if isAuthenticated() && resource.data.promoterId == request.auth.uid;
}

match /fightfeed_posts/{postId} {
    allow read: if true;
    allow update: if isAuthenticated() && (
        resource.data.userId == request.auth.uid ||
        request.resource.data.diff(resource.data).affectedKeys().hasOnly(['kos', 'techs', 'iqs', 'hypes'])
    );
}

loginForm.addEventListener('submit', async (e) => {
    e.preventDefault();
    const email = document.getElementById('login-email').value.trim();
    const password = document.getElementById('login-password').value;

    try {
        const userCredential = await signInWithEmailAndPassword(auth, email, password);
        const uid = userCredential.user.uid;

        const userDoc = await getDoc(doc(db, 'users', uid));
        if (userDoc.exists()) {
            const data = userDoc.data();
            localStorage.setItem('userRole', data.role);
            localStorage.setItem('userId', uid);
            localStorage.setItem('userEmail', email);

            if (data.role === 'promoter') window.location.href = 'promotor-dashboard.html';
            else if (data.role === 'fighter') window.location.href = 'fighter-dashboard.html';
            else window.location.href = 'fan-dashboard.html';
        }
    } catch (err) {
        console.error('Error en autenticación:', err.message);
    }
});

Explicación Técnica de la Pantalla

Propósito: Constituye el punto único de entrada autenticado al sistema. Renderiza un formulario asíncrono con conmutación dinámica de pestañas (Login, Registro Promotora, Registro Atleta) y fondo procedural en Canvas animado.

Flujo de Datos y Eventos: Escucha el evento submit en #login-form. Delega las credenciales a signInWithEmailAndPassword de Firebase Auth. Tras la resolución del JWT, consulta el documento users/{uid} para extraer el atributo inmutable role. Persiste userRole y userId en localStorage y redirige al dashboard especializado sin recargas innecesarias.

Seguridad: Manejo de excepciones de Firebase (auth/user-not-found, auth/wrong-password) con mensajes neutrales para prevenir ataques de enumeración de usuarios.

export async function comprimirAvatarCanvas(file, maxDim = 400) {
    return new Promise((resolve) => {
        const reader = new FileReader();
        reader.onload = (ev) => {
            const img = new Image();
            img.onload = () => {
                const canvas = document.createElement('canvas');
                canvas.width = maxDim;
                canvas.height = maxDim;
                const ctx = canvas.getContext('2d');
                ctx.drawImage(img, 0, 0, maxDim, maxDim);
                resolve(canvas.toDataURL('image/webp', 0.82));
            };
            img.src = ev.target.result;
        };
        reader.readAsDataURL(file);
    });
}

const CACHE_KEY = 'fc_live_combat_news_v4';
const CACHE_TTL_MS = 15 * 60 * 1000; // 15 minutos

async function obtenerNoticiasCombate() {
    const rawCache = localStorage.getItem(CACHE_KEY);
    const lastTime = localStorage.getItem('fc_news_time');
    
    if (rawCache && lastTime && (Date.now() - parseInt(lastTime) < CACHE_TTL_MS)) {
        return JSON.parse(rawCache);
    }

    const response = await fetch(API_SOURCES.ufc_espn);
    const payload = await response.json();
    const normalized = parsearArticulosESPN(payload.articles);

    localStorage.setItem(CACHE_KEY, JSON.stringify(normalized));
    localStorage.setItem('fc_news_time', Date.now().toString());
    return normalized;
}

Troubleshooting y Preguntas Frecuentes Técnicas

¿Por qué la verificación de Nivel 2 debe ser validada por Firestore Rules?

Porque cualquier atacante podría inspeccionar el DOM, modificar el objeto userData.isVerified = true y publicar eventos ficticios. Al bloquear la mutación de isVerified en firestore.rules (líneas 41-43), la integridad del ecosistema queda 100% blindada a nivel de base de datos.

¿Cómo se sirven las capturas de pantalla de los manuales?

Cada manual tiene su propia carpeta física independiente: manual-usuario/screenshots/ y manual-programador/screenshots/. Todas las rutas se invocan relativamente mediante ./screenshots/[nombre].png, asegurando que carguen tanto en file:/// como en servidores de desarrollo o producción.

¿Cómo ejecutar una compilación de producción validada?

Ejecuta npm run build. Vite escaneará todas las páginas HTML raíz más los dos manuales en sus subdirectorios autónomos, generando los paquetes minificados y optimizados en la carpeta dist/.
